# Verification checklist for test integrity

Paste this list into every verification subagent prompt. For each new or changed test, the subagent says which item (if any) applies, with `file:line`. Each item is a way a test can pass while proving nothing; every one of them was found in real factory pull requests.

1. **Assertion before the action.** An assertion that runs before `render()`, before the request, or before the event it is meant to observe checks a freshly built object and always passes. The "nothing is requested while hidden" check must render the hidden state first, then assert.
2. **The fake never reaches the code under test.** A test that builds a fake client or spy but renders the component with `client={null}` (or through a provider it never passes the fake to) asserts on an object the production code never touched.
3. **The mock swallows the behaviour.** A module mocked to a no-op (a realtime subscription, a fetch wrapper such as `withPlatformAuth`, a timer) cannot fail when the behaviour it stands for changes. Make the mock record its arguments and assert on them.
4. **Spy on the wrong layer.** A spy on the global `fetch` while the client goes through a wrapper that is itself mocked sees no request whatever the code does. Spy on the factory or client method the production code actually calls.
5. **Assertion on something the test built.** A contract or snapshot test that compares an object with a copy the test constructed, or a golden file regenerated from the implementation, agrees with itself. The expectation must be written independently of the code.
6. **One-directional contract check.** A drift test that only checks producer fields exist in the consumer (or the reverse) misses the other direction. Both directions must fail.
7. **Presence instead of gating.** `length > 0` where the requirement is "only the author sees Edit" passes when everyone sees it. Assert the exact count, with a second actor's item present, and the negative case.
8. **Only the negative case.** A behaviour asserted only as absent (Reply is not shown on a trashed file) passes on a build where it never renders at all. Assert the positive case too.
9. **Named for what it does not assert.** A test called "keeps its position" that never compares coordinates, or "saves with the precondition" that performs no save. Either assert what the name says or rename it.
10. **Self-fulfilling reset.** A "reload resets the state" test that calls the reset function itself and then asserts the reset happened.
11. **Rename that drops assertions.** A commit described as "rename only" or "traceability" must change names and comments only. Diff each such file (`git diff -w`) and confirm every assertion line survived.
12. **Timing that decides the result.** A real-timer debounce racing a `waitFor` default, a `user.type` into a controlled input, an `await` that lets a scheduled frame land before the assertion. The test passes or fails by load, not by behaviour. Fake timers, a single paste, or a synchronous `fireEvent` inside `act` make the observation deterministic.
13. **Planner or environment dependence.** An `EXPLAIN` test that relies on the planner's free choice, or a copy of the SQL instead of the generated statement, can flake or check the wrong query. Plan the exact generated SQL and constrain the planner (`SET LOCAL enable_seqscan = off`) or seed enough rows.
14. **Structural guard that matches the wrong thing.** A source-scanning test that matches a client call site (`.listThreads(`) misses a new component that reaches the same data through a hook, a re-export, an alias or a dynamic import. Guard the readers (who imports the hook) as well as the call sites.
15. **Unrequested production change.** Any production file a fix or "test-only" commit touches beyond what was asked for: read it as carefully as the original diff. A change of layer, z-index, portal, focus handling or listener is where regressions hide (for example a button moved into a dialog-companion layer without honouring that layer's inert contract).
